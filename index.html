    Sesión 1 / 4.1 Arquitectura de aplicaciones Web

    Arquitectura de tres capas

    Una aplicación web separa sus responsabilidades para que cada parte cambie, escale y se proteja de forma independiente. El patrón más usado en sistemas de información es el de tres capas.

    Presentación cliente

    Interfaz que ve el usuario: HTML, CSS y JavaScript en el navegador. Captura datos, valida formato para la experiencia de uso y muestra resultados.

    Lógica de negocio servidor

    Reglas de la organización: autenticación, autorización, cálculos, validación definitiva y orquestación. Expone servicios (API REST, controladores).

    Datos SGBD

    Persistencia y resguardo: tablas, restricciones de integridad, transacciones, índices y respaldos. Solo la lógica accede a ella.

    Capa no es lo mismo que nivel. Una capa (layer) es una separación lógica del código; un nivel (tier) es dónde se despliega físicamente. Puedes tener tres capas en un solo servidor (un monolito bien organizado) o repartidas en tres máquinas. MVC, por su parte, es un patrón que organiza principalmente la presentación y su controlador; no reemplaza a las tres capas.

      Sesión 1 / 4.2 Lenguajes del lado del cliente

      Lenguaje script del cliente

      JavaScript, estandarizado como ECMAScript, es el lenguaje que el navegador ejecuta para que la capa de presentación responda sin recargar la página.

      Motor

      Cada navegador trae un motor: V8 (Chrome, Edge), SpiderMonkey (Firefox), JavaScriptCore (Safari). Compila el código al vuelo (JIT).

      Sandbox

      El script corre aislado: no accede al sistema de archivos ni a otras pestañas, y la política de mismo origen limita sus peticiones.

      Un solo hilo

      Ejecuta una tarea a la vez con un bucle de eventos (event loop). Lo asíncrono (fetch, temporizadores, eventos) entra en colas.

      No es confiable

      El usuario controla su navegador: puede modificar o desactivar cualquier script. Por eso la seguridad real vive en el servidor.

      ¿Cómo se carga un script?

      <!-- Bloquea el análisis del HTML mientras descarga y ejecuta -->

<!-- Descarga en paralelo; ejecuta en orden al terminar de analizar el HTML -->

<script src="analytics.js" async></script>

<!-- Módulo ES: diferido por defecto, permite import/export -->

      Sesión 2 / 4.2.4 Eventos

      Eventos con lenguaje script

      Un evento es una señal de que algo ocurrió: un clic, una tecla, el envío de un formulario o la carga del documento. El script registra funciones (manejadores) que reaccionan a esas señales.

      const form = document.querySelector('#registro');

form.addEventListener('submit', (e) => {
  e.preventDefault();               // evita recargar la página
  const correo = form.correo.value.trim();
  if (!/^[^\s@]+@[^\s@]+\.[a-z]{2,}$/i.test(correo)) {
    form.correo.setCustomValidity('Correo inválido');
    form.reportValidity();
    return;
  }
  enviar({ correo });               // el servidor vuelve a validar
}, { passive: false });

      El objeto evento

      • e.target: dónde se originó
      • e.currentTarget: quién lo está manejando
      • e.preventDefault(), e.stopPropagation()

      Opciones

      • capture: escuchar en la fase de captura
      • once: se elimina tras ejecutarse
      • passive: promete no llamar a preventDefault

      Tipos frecuentes

      • Ratón: click, mousedown, mouseover
      • Teclado: keydown, keyup
      • Formulario: input, change, submit
      • Documento: DOMContentLoaded, load

      Laboratorio de propagación

      Un evento viaja en tres fases: captura (de la raíz hacia el objetivo), objetivo y burbujeo (del objetivo hacia la raíz). Activa las opciones y haz clic en cualquier caja o en el botón.

      Delegación de eventos. En lugar de poner un listener a cada <li>, se coloca uno en el contenedor y se usa e.target.closest('li'). Funciona con elementos agregados después, consume menos memoria y es la base de cómo los frameworks manejan listas.
